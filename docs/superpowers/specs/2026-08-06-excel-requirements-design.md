# 具身智能平台四板块 Excel 需求开发文档设计

## 1. 目标

基于参考文件 `/Users/zhangxiaozhang/Desktop/任务管理.xlsx` 的任务清单形式，重新整理当前项目的“数据采集、数据标注、标注工作台、模版中心”四个板块，生成一份可用于需求澄清、全栈开发分工、进度跟踪和验收的 Excel 文档。

团队采用“一个负责人承担一个板块的前端、后端、数据、交互和联调”的交付方式，因此文档不再拆分前端负责人、后端负责人和平台负责人。每个模块仅设置一个模块负责人，同时把前端与交互要求、后端/API 与数据要求、业务规则和验收标准分列记录，确保责任统一但交付边界清晰。

## 2. 信息来源与口径

- 参考格式：`/Users/zhangxiaozhang/Desktop/任务管理.xlsx`。
- 当前项目：`/Users/zhangxiaozhang/Desktop/具身智能平台原型/0714/prototype`。
- 功能范围以当前项目中的菜单、页面、表单、列表字段、弹窗、按钮和交互为基础补全。
- “页面上出现”只表示原型可见，不等同于后端持久化、权限、异常处理和端到端验收完成。
- Excel 中的默认开发阶段统一设为“待开始”，避免把原型展示误记为已交付。

## 3. 工作簿结构

最终工作簿包含六张表。

### 3.1 使用说明

说明文档用途、负责人模式、字段含义、状态流、优先级、测试结果和填写规则。

重点说明：

- 一个模块只有一个模块负责人。
- 模块负责人对前端、交互、接口、数据、权限、异常、联调、自测和交付结果负责。
- 需求必须以可独立验收的功能点为最小粒度。
- 功能可见、数据持久化、刷新恢复和权限校验分别验收。
- 需求状态只能按规定状态流推进。

### 3.2 开发总览

每个模块占一行，字段为：

1. 模块
2. 模块负责人
3. 需求总数
4. 已完成数
5. 进行中数
6. 阻塞数
7. 完成率
8. P0 数量
9. P1 数量
10. 计划工时
11. 已投入工时
12. 当前阶段
13. 风险与下一步

“需求总数、已完成数、进行中数、阻塞数、完成率、P0 数量、P1 数量、计划工时、已投入工时”使用跨表公式统计，不手工填写。

模块负责人使用以下角色占位：

- 数据采集负责人
- 数据标注负责人
- 标注工作台负责人
- 模版中心负责人

### 3.3 四个模块需求表

工作表名称：

- 数据采集
- 数据标注
- 标注工作台
- 模版中心

四张表使用相同字段结构，便于统一筛选和汇总。

## 4. 模块需求表字段

字段按以下顺序设置：

| 序号 | 字段 | 用途 |
| --- | --- | --- |
| 1 | 需求ID | 模块前缀加三位流水号，分别为 COL、ANN、WB、TPL |
| 2 | 一级板块 | 数据采集、数据标注、标注工作台或模版中心 |
| 3 | 页面/功能域 | 列表、新建、详情、工作台、任务模版等 |
| 4 | 功能点 | 可独立开发和验收的功能名称 |
| 5 | 需求描述 | 从业务使用者角度说明要实现什么 |
| 6 | 前端与交互要求 | 页面字段、按钮、弹窗、联动、状态反馈和跳转行为 |
| 7 | 后端/API与数据要求 | 接口、数据模型、查询、写入、事务、持久化和审计要求 |
| 8 | 业务规则与状态流 | 状态变化、计算规则、前置条件和跨模块流转 |
| 9 | 异常、权限与边界 | 空状态、失败、重复提交、越权、删除保护和边界值 |
| 10 | 验收标准 | 使用编号列出可复现、可判断通过或失败的验收项 |
| 11 | 依赖项 | 前置页面、基础数据、接口、角色或其他需求ID |
| 12 | 优先级 | P0、P1、P2 |
| 13 | 模块负责人 | 四个角色占位之一，后续可替换为姓名 |
| 14 | 预估工时(h) | 数值，包含本需求前端、后端、交互和联调总工时 |
| 15 | 已投入工时(h) | 数值，由负责人更新 |
| 16 | 开发阶段 | 待开始、前端与交互、API与数据、联调中、待验收、已完成、已阻塞 |
| 17 | 开始日期 | 真实日期值 |
| 18 | 计划完成日期 | 真实日期值 |
| 19 | 实际完成日期 | 真实日期值 |
| 20 | 测试结果 | 未测试、通过、不通过、部分通过 |
| 21 | 对应页面/原型 | 当前项目路由或本地文件位置 |
| 22 | 备注 | 变更、风险、阻塞原因和补充说明 |

## 5. 状态、优先级与验证规则

### 5.1 开发阶段

允许值：

1. 待开始
2. 前端与交互
3. API与数据
4. 联调中
5. 待验收
6. 已完成
7. 已阻塞

推荐流转为“待开始 → 前端与交互/API与数据 → 联调中 → 待验收 → 已完成”。“已阻塞”可以从任一未完成状态进入，但备注中必须填写阻塞原因和解除条件。

### 5.2 优先级

- P0：主流程不可缺失，不完成则模块无法交付。
- P1：高频业务能力或重要异常保护，应纳入当前版本。
- P2：体验优化、低频能力或后续增强。

### 5.3 测试结果

- 未测试
- 通过
- 不通过
- 部分通过

只有开发阶段为“已完成”且测试结果为“通过”的需求，才计入总览中的已完成数。

## 6. 模块功能范围

### 6.1 数据采集

需求覆盖：

- 采集任务列表字段、分页、状态页签和多维筛选。
- 新建采集任务的“需要采集数据”和“关联数据资产/外部导入”双模式。
- 项目、任务书、场景、用途、采集模式、遥操类型和设备配置联动。
- 采集数量、设备部件参数和 Episode 数据选择。
- SOP 动作步骤导入、新增、删除、排序和帧区间生成。
- 采集任务详情、统计卡片、分包/实例列表和进度汇总。
- 分包新增、编辑、人员分配、暂停和状态跟踪。
- 批量添加标注、批量完成以及实际采集量不足时的前置阻断校验。
- 查看、编辑、复制、删除及被引用/已产生数据时的删除保护。
- 采集完成后自动生成或关联数据标注任务。
- 权限校验、重复提交保护、操作日志和刷新后状态恢复。

### 6.2 数据标注

需求覆盖：

- 标注任务列表字段、多维筛选、分页和状态页签。
- 标注任务查看、编辑、复制和删除。
- 批量分派标注员和审核员。
- 从已采集数据、数据资产或外部数据建立标注任务。
- 基础信息、项目、场景、任务书/标注模版配置。
- Episode 数据筛选、数量输入与勾选列表双向联动。
- 标注类型、SOP 动作步骤和模版导入。
- 标注任务详情、数据包/实例进度和人员配置。
- 标注、审核和完成进度汇总。
- 分派冲突、无可用数据、重复数据、删除引用和无权限操作处理。

### 6.3 标注工作台

需求覆盖：

- 标注任务 Episode 明细列表、状态页签和人员分配。
- 多视角视频网格、视角切换和同步播放。
- 点标注、框标注、范围标注和语义时序标注。
- 播放、暂停、首尾帧、逐帧、倍速和进度定位。
- 视频播放轴与红线标注游标独立控制。
- 点击或拖拽红线游标定位，点击步骤自动跳转起始帧。
- 动作步骤卡片的增删、排序、起止帧编辑和时序轴双向联动。
- 结构化动作、自然语言动作和动作模版导入。
- 保存暂存、刷新恢复、异常恢复和重复保存保护。
- 生成标注模版、套用标注模版和套用后人工核验。
- 快捷键、上一条/下一条和完成后自动进入下一条。
- 完成标注、质检不合格、抽检通过和抽检不通过。
- 标注覆盖率、错误帧、质量状态和操作日志。

### 6.4 模版中心

需求覆盖：

- 任务模版、动作模版和标注模版三个页签。
- 模版搜索、类型筛选、创建人筛选、空状态和分页/卡片展示。
- 任务模版新建、编辑、查看、克隆、删除和“在任务中心使用”。
- 任务模版名称、编码、设备、采集模式、描述和 SOP 步骤配置。
- 动作模版结构化步骤和自然语言步骤双模式。
- 动作步骤执行末端、原子技能、对象、目标和默认帧区间。
- 新增步骤帧区间自动推算、步骤排序和删除。
- 标注模版从工作台生成、集中展示、预览、删除和复用。
- 模版被任务或标注引用时的修改/删除保护。
- 模版保存失败、重复编码、无权限和刷新持久化验证。

## 7. 公式与可编辑性

- 开发总览只通过公式引用四个模块表，不复制需求明细。
- 完成率公式为“已完成且测试通过的需求数 ÷ 需求总数”。
- 计划工时和已投入工时使用求和公式。
- 优先级、开发阶段、测试结果和模块负责人设置下拉验证。
- 日期列使用真实日期格式 `yyyy-mm-dd`。
- 工时列使用数值格式 `0.0`。
- 完成率使用百分比格式 `0%`。

## 8. 视觉设计

- 延续参考表的横向任务清单形式，但增加清晰的标题区、说明区和状态色。
- 冻结表头所在行和前四列，打开筛选按钮，便于在宽表中浏览。
- 长文本自动换行，需求描述和验收标准列设置更宽。
- 使用颜色区分 P0/P1/P2、开发阶段和测试结果。
- 不使用大面积装饰性图表；开发总览以紧凑的汇总表为主。
- 隐藏默认网格线，使用轻量边框定义表格结构。
