# 标注完成自动生成质检包设计

## 目标

当数据标注任务达到“全部标注完成”时，系统自动在“数据质检”板块生成一条关联质检包。质检包与原标注任务一一对应；同一标注版本重复同步不得生成重复记录，返工后的新版本沿用原质检包并增加质检轮次。

## 当前项目约束

- 项目是 Next.js 16 App Router 原型，业务列表主要由客户端组件和本地模拟数据组成。
- 当前没有真实后端接口或数据库，因此本次使用浏览器 `localStorage` 模拟跨页面持久化。
- 不改造现有页面布局，只补齐标注任务与质检列表之间的数据闭环。
- 不覆盖或删除现有演示质检数据；自动生成的质检包显示在列表顶部。

## 数据模型

质检包保存以下核心字段：

- `qaPackageId`：稳定ID，格式为 `QA-{标注任务ID}`。
- `annotationTaskId`：来源标注任务ID。
- `annotationVersion`：当前提交的标注结果版本，默认从 1 开始。
- `currentRound`：当前质检轮次。
- `rounds`：历次质检轮次、标注版本、提交时间和状态。
- `qcStatus`：新生成或返工重提后为“待质检”。
- `dataCount`、`annoType`、项目、任务书、标注员等列表展示字段。

浏览器存储键固定为 `embodied_qa_packages`。

## 业务流程

1. 标注任务页面加载任务数据。
2. 对满足 `status=已完成` 且 `finishCount >= totalCount` 的任务执行质检包同步。
3. 若不存在对应质检包，创建第 1 轮质检记录。
4. 若已存在相同标注版本，保持原记录不变，避免重复创建。
5. 若返工后提交了更高标注版本，沿用原 `qaPackageId`，新增一轮记录并将状态重置为“待质检”。
6. 数据质检页面读取 `embodied_qa_packages`，将自动生成的记录置于演示数据之前。

## 页面反馈

- 标注任务列表新增“质检包”列，显示自动生成的质检包ID和当前状态。
- 操作区为已生成记录提供“查看质检”入口。
- 首次自动生成时提示生成数量；重复进入页面不重复提示、不重复建包。
- 数据质检列表中自动生成记录可搜索、分配质检员并进入详情。

## 异常和边界

- 未完成任务不生成质检包。
- 缺少任务ID、总数非法或本地存储损坏时安全返回，不影响页面已有数据。
- 同一任务同一版本重复执行必须幂等。
- 质检员重新分配后写回本地质检包，刷新页面仍保留。

## 验收标准

1. 已完成标注任务自动生成一条“待质检”质检包。
2. 未完成任务不生成。
3. 同一版本重复同步不增加质检包或轮次。
4. 新版本重提沿用质检包ID并增加轮次。
5. 标注任务列表能看到质检包并跳转到质检详情。
6. 数据质检列表能看到自动生成记录，刷新后仍存在。
7. 项目构建通过，核心流程单元测试通过。
