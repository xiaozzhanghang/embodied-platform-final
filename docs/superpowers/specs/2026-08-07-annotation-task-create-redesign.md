# 新建标注任务页面改版设计

## 目标

把“创建标注任务”从依赖采集任务和模板的复杂表单，改成以可标注数据为核心的轻量创建流程。创建任务只强制任务名称、标注类型和待标注 Episode；动作模板、标注样例模板都是可选的效率工具。

## 页面结构

页面采用单页三段式布局：

1. **任务信息**：标注任务名称、标注类型、任务用途和说明。名称、类型必填，其余选填。
2. **选择待标注数据**：从唯一的统一可标注数据池中，通过场景、子场景和来源名称或 Episode ID 筛选可标注 Episode。默认展示全部可用数据，不强制关联采集任务；页面不得提供来源类型切换条、标签页或 `sourceType` 筛选状态。
3. **可选加速配置**：默认“无模板开始”，另可选择“动作模板/SOP”或“标注样例模板”。只有选择对应模式时才显示具体模板选择框。

## 数据来源

采集完成数据、校验通过的资产数据和仿真数据都汇入唯一的可标注数据池。原始来源类型和来源名称仅作为表格追溯列展示，不是页面顶层筛选条件。

场景、子场景、来源名称或 Episode ID 均是筛选条件，不是创建任务的必填依赖。数据表展示 Episode ID、原始来源类型、原始来源名称、场景、帧数和可用状态。

## 模板逻辑

- 默认模式为 `none`，文案为“无模板开始”。
- `action` 模式选择动作模板/SOP，用于预置动作步骤。
- `sample` 模式选择已审核发布的标注样例模板，用于进入工作台后的批量套用。
- 创建任务时不允许同时选择动作模板和标注样例模板，避免用户理解成本。
- 模板不影响任务发布资格；发布资格仅取决于任务名称、标注类型和至少一条 Episode。

## 视觉方向

延续当前平台的浅色企业后台风格，使用蓝青色强调“数据就绪”，用浅灰分区降低长表单压力。模板模式使用三张可点击卡片呈现，让“可选”一眼可见。页面顶部显示三步流程提示：任务信息、选择数据、可选配置。

## 验收标准

- 页面默认处于无模板模式。
- 数据来源固定为唯一的统一可标注数据池；页面没有 `Segmented`、来源类型切换条、标签页或 `sourceType` 筛选状态。
- 页面明确说明无需先创建或选择采集任务。
- 选择不同模板模式时仅出现对应模板字段。
- 至少选择一条 Episode 后可发布任务。
- 构建通过，页面在 `http://localhost:3000/collection/annotation-tasks/create` 可正常展示。
