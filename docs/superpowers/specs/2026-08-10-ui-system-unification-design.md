# 全站 UI 组件与显示样式统一设计

## 1. 背景与目标

当前原型已覆盖数据采集、数据标注、标注工作台、数据质检、模板中心、数据资产和系统管理等模块，但页面之间同时存在 Ant Design 默认样式、自定义深色样式、渐变卡片和大量页面级内联样式。相同功能在标题、筛选区、按钮、状态标签、表格、表单和弹窗上呈现不一致。

本次改造以现有 Ant Design 蓝色后台风格为唯一视觉基准，建立可复用的页面与业务组件，并逐步替换页面级重复样式。改造完成后，所有后台页面应具有一致的视觉语言和交互反馈，同时保持已有数据结构、业务流程、路由和接口行为不变。

## 2. 已确认的设计方向

- 主色沿用 Ant Design 蓝 `#1677FF`。
- 页面背景使用 `#F5F7FA`，主要内容容器使用白色。
- 后台采用紧凑、清晰、信息密度适中的企业管理系统风格。
- 登录页允许保留独立构图，但字体、主色、控件和反馈状态必须与后台一致。
- 创建、编辑和配置使用居中弹窗；只读复杂详情使用详情页。
- 标注与质检工作台保留高信息密度布局，但组件外观和状态语义必须统一。
- 不修改业务字段、数据模型、接口、权限逻辑和核心流程。

## 3. 改造范围

### 3.1 全局基础

- Ant Design `ConfigProvider` 主题 token。
- 全局 CSS 变量、字体、背景、间距、圆角、阴影和边框。
- 主导航、顶部栏、内容区宽度和页面内滚动行为。
- 全局加载、空数据、错误、禁用、悬停和焦点状态。

### 3.2 公共组件

- 页面头部：面包屑、标题、说明和右侧操作。
- 筛选面板：字段布局、展开/收起、查询和重置。
- 表格工具栏：结果统计、批量操作、刷新、导出和新建。
- 数据表格：表头、密度、对齐、操作列、分页和空状态。
- 状态标签：统一状态名称与颜色映射。
- 表单分区：分组标题、字段说明、必填提示和校验反馈。
- 居中弹窗：标题、内容滚动、底部按钮和关闭确认。
- 统计卡片、详情描述区、步骤条、时间线和结果反馈。

### 3.3 页面类型

- 列表页。
- 新建与编辑页。
- 详情页。
- 标注与质检工作台。
- 登录页和采集员页面。

覆盖 `src/app` 下现有全部业务路由，优先处理数据采集、数据标注、标注工作台、数据质检和模板中心，再处理数据资产、系统管理、登录及其他辅助页面。

## 4. 视觉规范

### 4.1 色彩

| 用途 | 色值 |
| --- | --- |
| 主色 | `#1677FF` |
| 页面背景 | `#F5F7FA` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#1F2329` |
| 次文字 | `#646A73` |
| 辅助文字 | `#8F959E` |
| 边框 | `#E5E6EB` |
| 成功 | `#52C41A` |
| 警告 | `#FAAD14` |
| 错误 | `#FF4D4F` |
| 禁用 | `#BFBFBF` |

页面不得自行引入新的品牌主色。业务图表可以使用扩展色板，但操作按钮、链接和选中状态必须使用主色。

### 4.2 字体与层级

- 页面标题：20px，600。
- 区块标题：16px，600。
- 正文与表格：14px，400。
- 辅助说明：12px，400。
- 数字统计可使用 24px，600，但不得使用装饰性字体。

### 4.3 尺寸与间距

- 基础间距阶梯：4、8、12、16、24、32px。
- 页面内边距：24px；窄屏下为 16px。
- 卡片圆角：8px。
- 表单、筛选和按钮默认高度：32px。
- 主要弹窗宽度按内容使用 520、720、960px 三档。
- 卡片之间默认间距：16px；主要页面区块之间为 24px。

### 4.4 阴影与边框

- 普通内容卡片主要依靠 `1px` 边框区分，不使用明显阴影。
- 弹窗、下拉菜单和悬浮层使用 Ant Design 默认层级阴影。
- 删除页面自行定义的彩色投影、发光和无业务含义的渐变背景。

## 5. 公共组件设计

### 5.1 `PageHeader`

负责显示面包屑、页面标题、说明、返回操作和右侧主要操作。标题区不再套用额外的大型渐变卡片。同一页面只出现一个一级标题。

### 5.2 `FilterPanel`

筛选字段按栅格排列。默认展示高频条件，其余条件通过“展开”显示。查询为主按钮，重置为普通按钮。查询、重置和展开位置在所有列表页保持一致。

### 5.3 `TableToolbar` 与 `DataTable`

工具栏左侧显示结果数量或批量选择信息，右侧依次放置次要操作和主要新建按钮。表格统一表头背景、单元格内边距、操作列宽度、分页位置和空状态。操作超过三个时收纳到“更多”。

### 5.4 `StatusTag`

状态颜色仅表达语义：进行中和处理中为蓝色，成功和已完成为绿色，待处理和待审核为橙色，失败和驳回为红色，未开始、停用和已取消为灰色。页面不得自行定义同义状态的不同颜色。

### 5.5 `FormSection` 与 `ActionFooter`

长表单按业务含义分区，每个分区包含标题和可选说明。字段错误紧邻控件显示。页面式表单使用固定顺序的取消、保存草稿和提交按钮；不具备草稿业务时不显示保存草稿。

### 5.6 `AppModal`

创建、编辑和配置统一使用居中弹窗。标题和关闭按钮固定在顶部，内容超高时仅内容区滚动，底部操作保持可见。存在未保存内容时关闭需二次确认。抽屉不用于创建或编辑流程。

### 5.7 `StateView`

统一加载、空数据、查询无结果、无权限和加载失败状态。错误状态必须提供清晰说明及可执行的重试或返回操作。

## 6. 页面模板

### 6.1 列表页

顺序固定为页面头部、筛选面板、表格卡片。表格卡片内部先显示工具栏，再显示表格和分页。简单列表不得额外增加统计横幅。

### 6.2 新建与编辑页

使用页面式表单或居中弹窗。页面式表单适合字段多、存在步骤或需要大范围数据选择的流程；普通创建和编辑使用弹窗。提交成功后返回列表或进入详情，失败时保留已输入内容。

### 6.3 详情页

使用基础信息、进度统计、关联数据和操作记录四类区块。页面操作集中在标题右侧，不在各卡片中重复放置同一操作。

### 6.4 标注与质检工作台

允许使用独立的多栏布局和更紧凑的控件密度。顶部任务信息、中央作业区、左右工具面板和底部操作区采用一致的边框、背景和状态色。保存、提交、通过和驳回必须具有明确且不同的反馈。

### 6.5 登录与采集员页面

登录页可使用独立背景，但移除与后台主色冲突的紫色品牌主视觉。采集员页面可以简化导航，但按钮、表单、列表和状态标签与后台共用同一套组件。

## 7. 交互与反馈

- 所有提交按钮在请求期间进入加载状态并阻止重复提交。
- 成功操作使用统一成功消息；失败操作显示可理解的原因。
- 删除、作废、驳回和覆盖等不可逆操作必须二次确认。
- 表格查询条件、分页和排序在返回列表时尽量保留。
- 键盘焦点必须可见，弹窗打开后焦点进入弹窗，关闭后返回触发控件。
- 禁用控件同时提供禁用原因，不能只依靠颜色表达状态。

## 8. 技术方案

### 8.1 主题层

在现有 `AntdRegistry` 中扩展 `ConfigProvider` token，集中定义颜色、圆角、字体、控件高度以及 Button、Card、Table、Modal、Form、Tabs、Tag 等组件级 token。

### 8.2 样式层

将 `globals.css` 整理为设计 token、布局基础、公共组件和兼容覆盖四个区域。新增样式使用语义类名，不以具体颜色或页面名称命名。页面级样式只保留业务布局，不重复定义通用组件外观。

### 8.3 组件层

在 `src/components/ui` 下建立小型公共组件。公共组件只负责一致的外观、布局和基础行为，不承载页面业务请求。页面继续负责数据获取、状态管理和业务事件。

### 8.4 迁移策略

迁移按四个可独立验收的阶段进行：

1. 全局主题、主布局和公共组件。
2. 数据采集、数据标注、标注工作台、数据质检和模板中心。
3. 数据资产、系统管理、登录、采集员及辅助页面。
4. 删除失效的重复样式并进行全路由回归。

每个阶段必须保持项目可启动，且已迁移页面不得依赖尚未迁移页面的私有样式。

## 9. 兼容与响应式

- 主要验收宽度为 1440px 和 1920px。
- 页面在 1280px 仍应可操作，不出现主要按钮被遮挡或表单标签重叠。
- 数据表格允许横向滚动，不压缩关键列到不可读状态。
- 弹窗宽度不得超过视口，内容区超高时内部滚动。
- 不为手机端重构完整后台流程，但登录页与采集员页面需支持常见移动宽度。

## 10. 验证与验收

### 10.1 自动检查

- 执行现有 lint、构建和测试命令。
- 新增公共组件的渲染和关键行为检查。
- 扫描页面中新出现的非规范颜色、圆角和重复样式。
- 检查所有路由能够正常编译和访问。

### 10.2 浏览器验收

- 抽查并截图五类页面模板在 1440px 与 1920px 下的显示。
- 验证筛选、重置、分页、弹窗打开与关闭、表单校验和主要操作反馈。
- 检查加载、空数据、无结果、错误和禁用状态。
- 对核心五个模块逐路由检查，不以首页显示正常代替全站验收。

### 10.3 完成标准

- 相同类型组件在不同模块中外观和行为一致。
- 页面不再自行定义主色、通用按钮、通用表格和通用弹窗样式。
- 核心五个模块及其工作台完成逐页验证。
- 其余路由完成编译检查和代表性页面浏览器验证。
- 现有业务操作仍可执行，未因样式迁移改变数据和流程。

## 11. 非目标

- 不重写业务接口和数据模型。
- 不重新规划导航信息架构。
- 不新增与样式统一无关的业务功能。
- 不将桌面后台整体重构为移动端应用。
- 不引入新的 UI 组件库或 CSS 框架。
