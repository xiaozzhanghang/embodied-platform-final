# 第一部分：开发交付给运维的物料清单 (Dev to Ops Handover Checklist)

开发团队提交静态产物发布工单时，需向运维团队完整交付以下 **7 大项标准化物料**：

### 1. 代码版本与构建物料 (Code & Artifacts)
- **代码仓库**：`git@github.com:xiaozzhanghang/embodied-platform-final.git`
- **发布分支**：`codex/nextjs-static-export`
- **最终 Commit SHA**：发布时现场核验，不在本文件中预填尚未生成的提交号。依次执行：

```bash
git rev-parse HEAD
git ls-remote origin refs/heads/codex/nextjs-static-export
```

本地与远端 SHA 必须一致，且均指向已经通过本交接清单验收的最终提交，方可构建发布产物。
- **可部署目录**：`out/`
- **归档建议**：将安全检查通过的 `out/` 按最终 Commit SHA 归档，发布和回滚均使用该静态产物，不在目标环境二次构建。

### 2. 构建环境与静态托管要求 (Build & Hosting Requirements)
- **Node.js 构建环境**：`Node.js >= 20.9.0`；仅安装依赖、执行构建和发布前本地预览时需要。
- **包管理器**：使用仓库 lockfile 对应的 `npm ci`。
- **框架版本**：`Next.js 16.1.6`（内置 Turbopack 编译内核）
- **静态托管**：将 `out/` 内容发布到普通静态 Web 服务或 CDN；构建后不需要 Node.js 应用进程。
- **部署根路径**：`/`
- **Luming 数据说明**：页面仅使用可公开发布的合成 fixture，不包含真实采集数据。
- **导出安全净化**：`npm run build` 的 `postbuild` 会仅从生成的 `out/` 清除本机媒体副本和未纳入应用的旧原型页面，再执行私网地址、凭据、宿主绝对路径、符号链接、大文件及视频扩展名检查；不会修改 `public/` 源目录。
- **Netlify 边界**：本分支的 `out/` 独立发布流程不等同且不依赖现有 Netlify 插件流水线；若使用 Netlify，需另行验收其 publish 配置与产物一致性。

### 3. 配置文件与环境变量变更清单 (Environment Variables)
当前 `out/` 是公开、可复现的前端静态原型，不读取部署环境中的 `.env.production`。不得在静态产物中注入凭据、私网地址或真实采集数据。

### 4. 数据库变更与数据迁移脚本 (Database Migration DDL/DML)
- **本静态产物无数据库迁移**：部署 `out/` 不执行 DDL/DML。如有独立后端发版，其迁移与回退必须使用另行审批、已核验的交接文档。

### 5. 静态产物构建与预览命令 (Build & Preview Commands)
在已检出并锁定目标 Commit 的工程根目录执行：

```bash
npm ci
npm run build
npm start
```

`npm run build` 成功退出即表示自动安全净化通过。`npm start` 仅用于在发布前本地预览已生成的 `out/`。发布时只上传净化并验收通过的 `out/` 内容到站点根路径，并将该目录作为可原子切换、可归档的静态产物。

### 6. 健康检查与验证用例 (Health Check & Verification URLs)
静态产物部署完成后，需依次访问以下路径确认 HTTP 200 及演示页面渲染正常：
1. **数据质检首页**：`GET https://domain/collection/qa`
2. **数据审核列表**：`GET https://domain/annotation/audit`
3. **数据标注大厅**：`GET https://domain/annotation/projects`
4. **具身智能动作范围标注工作台**：
   `GET https://domain/annotation/workbench-solutions?instanceId=19884&episodeId=744108&type=范围标注&mode=annotate`
5. **PRD 文档抽屉验证**：在标注工作台右上角点击 `📋 功能需求说明书 (PRD)`，验证抽屉正常滑出且各 Tab 可切换。

### 7. 应急回滚方案 (Rollback Plan)
- **触发条件**：部署后出现核心工作台白屏、关键静态资源 404 或代表性深链无法打开。
- **回滚方式**：重新部署上一份已归档的 `out/` 静态产物。
- **回滚步骤**：
  1. 选择上一份通过验收并按最终 Commit SHA 归档的 `out/`；
  2. 在静态托管平台将当前产物原子切换为该归档；
  3. 刷新 CDN 边缘缓存，重新执行关键 URL 验证并通知业务方。

## 二、 本次发版功能清单 (Release Features)

> **能力边界**：以下功能均为 fixture-driven 静态演示；未接入后端、鉴权、持久化、结算或真实导出。

### 🌟 模块一：【静态演示】数据质检界面 (Data QA)
1. **多视角质检大盘**：用合成 fixture 展示多相机卡片、抽检覆盖率与状态统计；
2. **缺陷标记交互**：演示异常动作帧的本地交互与结果提示，刷新页面后不会保留；
3. **质检规则展示**：以静态示例呈现动作完整度、帧时序连续性等规则及结果。

### 🌟 模块二：【静态演示】数据审核界面 (Data Audit & Acceptance)
1. **审核工单列表**：用合成项目、批次和采集任务展示多维度列表；
2. **抽检决策交互**：演示单条 Episode 的通过或不通过选择及本地状态变化，不触发工单或结算；
3. **交付归档入口**：仅展示批量验收与归档入口，不生成真实归档文件。

### 🌟 模块三：【静态演示】数据标注界面 (Data Annotation)
1. **标注项目与任务中心**：用合成 fixture 展示长视频切分、范围标注、关键点标注等任务类型；
2. **进度与统计面板**：展示预置的标注进度、平均耗时与准确率，不连接实际人员或任务数据。

### 🚀 模块四：【静态演示】数据采集标注工作台 (Embodied Annotation Studio)
以下交互均在浏览器内演示，不会写入后端或持久化：
1. **手柄录制状态机 (Q/R 快捷键)**：
   - 点击 `开始 [Q]`：在合成 fixture 时间轴上记录本地起始帧并播放演示；
   - 点击 `标记 [R]`：记录本地结束帧并暂停演示；
2. **录制动态 HUD 横幅与视觉反馈**：
   - 演示期间顶部显示 HUD 横幅、fixture 帧差与动作描述；
   - 时间轴对应步骤呈现**蓝白交替发光动态斜纹（Barber-pole Stripes）**；
3. **3px 鲜艳激光红游标与拖拽联动**：
   - 采用 3px 鲜艳激光红实线、纯红角标与倒三角指针，全屏发光投影；
   - 支持在时间轴任意位置按住鼠标左右拖拽平滑寻帧（Scrubbing），滑过步骤区间自动联动高亮右侧对应步骤；
4. **动作步骤拖拽换位与复制管理**：
   - 支持鼠标按住 `⠿` 手柄上下拖拽演示步骤顺序，并在当前页面重新对齐时间轴；
   - 支持 `[复制单步]` 与多选 `[📋 批量复制]`、`[🗑️ 批量删除]` 的本地交互演示；
   - 新增步骤自动平滑滚动定位（`scrollIntoView`）；
5. **集成交互式 PRD 需求规格说明书抽屉**：
   - 页面右上角 `[📋 功能需求说明书 (PRD)]` 按钮可展开演示用需求与接口说明。
